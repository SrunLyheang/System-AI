Make the AI design agent feel alive: stream the canvas build one element at a time,
show a moving agent cursor, narrate each step with changing "thinking" messages,
gently follow the agent with the camera when it works off-screen, and replace the
single generic failure string with classified, actionable errors plus a Retry.

Builds on spec 26 (sidebar wiring) and spec 23 (the agent task). Backend + frontend.

### Background (current behaviour)

- `src/trigger/design-agent.ts` makes one `generateObject` Gemini call, then applies
  every node/edge in a single `mutateFlow` — the canvas jumps from empty to done
  after a multi-second static "Working…".
- `AiActivity.cursor` is written once (a static point) and rendered by nothing.
- Status text is one of ~5 hard-coded strings.
- Every failure collapses to "The design agent hit an error. Try again." in the
  canvas pill and the `ai-chat` feed.
- `ai-status-feed` is read by the sidebar strip but nothing writes it (always
  "Working…"). `Presence.thinking` is read by `CanvasCursor` but never set true.

### Decisions (fixed — do not re-litigate)

- Camera: follow only when the next target is off-screen.
- Thinking text: deterministic — rotating canned lines while planning, one narrated
  sentence per action while applying. No extra model call.
- Sidebar: a single changing status line (no accumulating log).
- Pacing: ~0.6s per step (glide 350ms + settle 250ms).

### Implementation

1. New module `lib/ai/agent.ts` (+ `lib/ai/agent.check.ts` self-check, `npx tsx`).
   Imports only `zod` and a type from `@/types/canvas`; `classifyError` imports
   nothing (duck-types) so the check runs without trigger/liveblocks/ai deps.
   - Move `actionSchema` + `type Action` here from the task; the task re-imports them.
   - Tunable constants with defaults: `GLIDE_MS=350`, `SETTLE_MS=250`,
     `THINKING_INTERVAL_MS=1800`, `THINKING_LINES` (6 lines),
     `CAMERA_MS=500`, `CAMERA_MARGIN_PX=80`, `CURSOR_FADE_MS=200`,
     `DONE_HIDE_MS=5000`, `MAX_ACTIONS=80`, `BATCH_SIZE=1`.
   - `narrate(action, labels: Map<string,string>): string` — `addNode`→`Adding "<label>"`;
     `addEdge`→`Connecting "<src>" to "<tgt>"` (labels via map, fall back to id);
     `updateNode`→`Refining "<label>"`; `moveNode`→`Repositioning "<label>"`;
     `resizeNode`→`Resizing "<label>"`; `deleteNode`→`Removing "<label>"`;
     `deleteEdge`→`Removing a connection`.
   - `targetPointOf(action, positions: Map, prev: {x,y}|null)` — action x/y for
     add/move; known node position for update/resize/delete; endpoint midpoint for
     edges; else `prev`; never non-finite (use `finiteNumber`).
   - `summarizeApplied(counts)` → e.g. `Added 8 nodes and 6 connections.`
   - `classifyError(error, ctx?: { applied; planned }): { kind: AiErrorKind; message }`
     — order: `applied > 0` → `partial` (`Applied N of M changes before hitting a problem.`);
     429 or /rate.?limit|quota|resource exhausted/i → `rate_limit`;
     /api key|\_API_KEY|SECRET_KEY|is not set|permission denied|unauthenticated/i → `config`;
     `NoObjectGeneratedError` / empty stream → `no_plan`;
     /fetch failed|ENOTFOUND|ECONNRESET|ETIMEDOUT|network|socket hang up/i → `network`;
     else `unknown`. Messages carry no stack or secret values.

2. `types/canvas.ts` — add `errorKind?: AiErrorKind` to `AiActivity`; export
   `type AiErrorKind = "config" | "rate_limit" | "no_plan" | "network" | "partial" | "unknown"`.
   Leave `types/tasks.ts` untouched (spec 27 may use `ai-status-feed`).

3. New hook `hooks/use-agent-status-text.ts` —
   `useAgentStatusText(ai: AiActivity | null | undefined): string`: rotates
   `THINKING_LINES` on a `setInterval` while `ai.status === "thinking"`, otherwise
   returns `ai?.message ?? ""`. Used by the pill and the sidebar strip.

4. `src/trigger/design-agent.ts` — stream instead of one shot:
   - Keep `getLiveblocks()` inside `try`; two `thinking` `setActivity` calls; snapshot.
   - `const result = streamObject({ model: google("gemini-3.6-flash"), output: "array",
schema: actionSchema, system: systemPrompt(nodes, edges), prompt })`.
   - `for await (const action of result.elementStream)` with `applied`/`planned` in
     outer scope: `planned++` (stop at `MAX_ACTIONS`); `cursor = targetPointOf(...) ?? cursor`;
     `setActivity({ status:"generating", message: narrate(action, labels), cursor })`;
     `await sleep(GLIDE_MS)`; `mutateFlow` applying that ONE action; record
     `labels`/`positions`; `applied++`; `await sleep(SETTLE_MS)`.
     `sleep = ms => new Promise(r => setTimeout(r, ms))`.
   - `planned === 0` and no throw → `status:"done"`, "No changes needed."
   - Success → `summarizeApplied(counts)` → `status:"done"`; return `{ summary, applied }`.
   - `catch`: `const { kind, message } = classifyError(error, { applied, planned })`;
     `logger.error`; best-effort `setActivity({ status:"error", errorKind: kind, message, cursor:null })`;
     `kind === "partial"` → `return { summary: message, applied }` (keep what landed,
     no retry — no per-action idempotency); otherwise `throw new AbortTaskRunError(message)`.

5. `components/editor/canvas/presence.tsx`:
   - New `AiCursor` — `useStorage(root => root.ai)`; local `pos` + `visible`; on
     `ai.cursor` change while `status` is `thinking`/`generating` set `pos` + show,
     else fade out (`CURSOR_FADE_MS`) then unmount (never snap). Render inside
     `<ViewportPortal>` (from `@xyflow/react`) as an absolutely-positioned `div` at
     `left/top = pos.x/pos.y` with `transition: left ${GLIDE_MS}ms cubic-bezier(.22,.61,.36,1), top …, opacity ${CURSOR_FADE_MS}ms`,
     `pointer-events:none`. Arrow SVG in `--accent-ai` + a "Design agent" pill (reuse
     `CanvasCursor`'s markup).
   - `AiActivityPanel` — label via `useAgentStatusText(ai)`. Auto-hide `done` only
     (`settled = status === "done"`, keep the `DONE_HIDE_MS` timer); `error` persists
     until `status` leaves `"error"`, with a small dismiss "×". Error styling:
     `lucide-react` `TriangleAlert` in `state-error`, `ai.message` verbatim.

6. `components/editor/canvas/index.tsx`:
   - Mount `<AiCursor />` inside `<ReactFlow>` after `<AiActivityPanel />`.
   - Camera-follow effect in `Canvas` (has `reactFlow` + `wrapperRef`), keyed on
     `ai?.cursor?.x/y` + `ai?.status`: only while `generating`/`thinking`; compute
     `wrapperRef.current.getBoundingClientRect()` and `reactFlow.flowToScreenPosition(ai.cursor)`;
     if outside the rect inset by `CAMERA_MARGIN_PX` →
     `reactFlow.setCenter(cursor.x, cursor.y, { zoom: reactFlow.getViewport().zoom, duration: CAMERA_MS, ease: easeOutCubic })`.
     On-screen target → no camera move.

7. `components/editor/canvas/ai-panel.tsx`:
   - `useStorage`/`useUpdateMyPresence` from `@liveblocks/react` (non-suspense).
     `const ai = useStorage(root => root.ai)`.
   - Status strip → `{useAgentStatusText(ai) || "Working…"}`; remove the
     `useFeedMessages(AI_STATUS_FEED_ID)` / `latestStatus` / `isAiStatusMessage`
     usage from this file only.
   - `onComplete(finished, error)`: prefer `ai?.status === "error" ? ai.message`;
     else `error` → generic; else `finished.status` `TIMED_OUT`/`CANCELED` → "The
     design took too long and was stopped."; else `finished.output?.summary`.
   - Retry: store `lastPrompt`; `submit(promptArg?)` uses `promptArg ?? draft`; a
     small "Retry" `Button` (shown while `canRetry`, disabled while `runActive`).
   - `submit()` fetch errors mapped by status: 401 / 404 / 429 / ≥500 / non-`Response`
     each get a specific message instead of one generic string.
   - Effect: `updateMyPresence({ thinking: runActive })` (+ cleanup to `false`) so
     collaborators see the existing spinner on the submitter's cursor.

### Scope Limits

- Do not change the API routes (`/api/ai/design`, `/api/ai/design/token`).
- Do not change the `gemini-3.6-flash` model id — only flag it if runs fail.
- Do not touch spec 27 / `generate-spec` or `types/tasks.ts`.
- Do not add an animation library — CSS transitions + React Flow `setCenter` only.
- Do not manually sync nodes/edges on the client — canvas changes still land through
  `useLiveblocksFlow`.
- `BATCH_SIZE` stays `1` (one node per write is the effect).

### Notes

- `streamObject` is `@deprecated` in `ai` 7.0.93 but works; `output: "array"` +
  `elementStream` yields one validated `Action` at a time.
- `GLIDE_MS` is shared: the task `sleep` and the `AiCursor` CSS transition both read it.
- Two concurrent runs in one room is a pre-existing race (full-object
  `root.set("ai", …)`), out of scope; the API idempotency key covers identical prompts.

### Check When Done

- `npx tsc --noEmit`, `npm run lint`, `npm run build` all pass.
- `npx tsx lib/ai/agent.check.ts` → `ok` (narrate, targetPointOf, summarizeApplied,
  classifyError kinds incl. `partial` with `{ applied, planned }`).
- Prompt "design a login flow with 6 steps": planning lines rotate, then per-step
  narration; the agent cursor glides to each target and the node appears ~0.25s later
  (~0.6s/step); pill and sidebar strip show the same text; on finish the pill shows
  "Added N nodes and M connections.", the cursor fades, the pill hides after ~5s, and
  the summary is posted to `ai-chat`.
- A second tab in the same room sees the same cursor + pill and a spinner on the
  submitter's cursor.
- Camera pans (eased) only when the next target is off-screen; manual panning over
  visible work is not yanked back.
- Forced failures: `no_plan` (empty array), `config` (unset `GEMINI_API_KEY`),
  `rate_limit` (stub 429), `partial` (throw on the 4th element — first 3 nodes stay,
  run succeeds), `TIMED_OUT` (`maxDuration: 5`) each produce a distinct, persistent
  error message in the pill and the `ai-chat` feed, with Retry offered where sensible.
